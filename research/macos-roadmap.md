## 2. 验收目标先围绕主题定义

选三种代表主题作为首版验收对象，避免围绕全部历史变量展开工作：

1. 文字/时钟/进度条主题：验证字体、布局、基础变量。
2. Lua+Cairo 圆环或钟表主题：验证绘图、渐变、透明与数据输入。
3. 图片/图标/复合布局主题：验证资源路径和混合渲染。

每个样本记录原始来源、目标截图、配置/脚本/资源、许可证、依赖与使用指标。用户喜欢的具体主题优先；目前下载的代码片段只是可行性证据，不自动成为最终验收主题。

视觉验收使用固定时间、固定 CPU/内存等输入、相同字体与逻辑尺寸；对照布局、颜色、曲线和资源位置，单独注明字体抗锯齿/替代的允许差异。随后再验证真实数据更新。外观接近与数据正确是两条独立验收线。

## 4. P1：先消除技术风险

### P1-A Swift 原生窗口、原生渲染与 Lua/Cairo

建议先在临时验证工程或独立实现分支验证：

- Swift 应用宿主和 AppKit 窗口，不绑定 Conky 全局主循环；参考其必要主题语义。
- AppKit 主线程、透明无边框窗口、鼠标穿透、确定的桌面层级。
- 一个原生文字/圆环主题，缓存布局/静态资源，按值变化更新。
- 再接通 Cairo image/Quartz 适配画布，明确生命周期和 points/pixels 换算。
- Swift 嵌入 Lua；实现所需的 `conky_parse()`、`conky_surface()` 与 `conky_window` 最小接口。
- 绘制一个修改后的真实圆环/钟表脚本，验证 pre/post hook 顺序。
- 单屏 Retina 先通过，再测试不同缩放、多屏以及显示桌面和 Spaces。

此时不做通用主题转换器、全面设置界面或多实例重构。风险验证失败时先确定是哪条接口或窗口语义不成立，再调整方案。

### P1-B macOS 数据

按样本实际需要扩展，不以传感器列表长度作为成果：

- 用 Swift 接入 CPU/网络/文件系统采集，参考并核对 Conky/Stats 的算法；多主题共享一次采样。
- 参考 Stats 调整内存口径，明确缓存、压缩、应用内存和总量。
- 用 IOPowerSources 补电池百分比和供电状态。
- 用 IORegistry 累计计数补磁盘 I/O，记录采样间隔和设备身份。
- SMC/HID 温度已证实可读，后续确认型号选择与无效值处理。
- 风扇数量已读到；RPM 还需验证停转/零值和 key 解释。
- IOReport 已证实可采样；CPU 功耗值为 0，需验证单位、通道聚合与负载响应。
- E/P 核频率须接通 pmgr 频点表与驻留差分，枚举到通道不算完成。

所有读数要有单位、来源、采样时间、可用性。读数暂不可用时用 N/A，避免在主题中伪造正常数值。监控首版无需风扇控制。

## 5. P2/P3：主题迁移的实现任务

按实际样本逐项建立支持表：

- 配置：Lua table、旧格式转换、窗口/字体/间隔/位置等必要项。
- 模板：时间、CPU、内存、磁盘、网络、电池与选定主题实际使用的条件/格式指令。
- 布局：color/font/offset/voffset/alignr/alignc/goto/tab 的真实行为。
- 图形：bar/graph/gauge、历史样本、渐变、背景透明、图片。
- Lua：require 路径、conky_parse、conky_window、surface、pre/post hook。
- 转换：识别 Xlib 画布模式，处理所有权/销毁，替换路径与接口名，输出人工处理项。
- 数据源：对 Linux 外部命令定义 macOS 替代或删除该部件；不一概静默忽略。

保留原始主题及迁移记录；转换后的代码先语法检查，再做固定数据渲染，最后做真实桌面验证。单纯“Lua 能加载”不算主题迁移成功。

## 6. P4/P5：产品化边界

单主题先稳定。新 Swift 核心按主题实例分离布局、历史与 Lua 状态，应用级共享采集和不可变快照。Conky 原核心有全局状态，不直接作为多实例宿主；个别高成本脚本是否隔离到辅助进程，由实测决定。

应覆盖的场景：普通桌面、显示桌面、不同 Space、全屏应用、Stage Manager 开关、多显示器、缩放变化、拔插显示器、睡眠唤醒、文件保存/替换触发重载、Lua 出错、主题资源缺失。

性能验证同时记录主题自身成本和采集成本；先测 1 Hz 更新，再按动画主题提高刷新。可见性/休眠时降低采样；高成本传感器与 UI 更新不必同频。

分发验证应确认 `.app` 内 Lua 模块、Cairo 和字体/图片路径可重定位，签名和动态加载可工作。保留 Conky GPL、Stats MIT 及资源许可告知；独立分发与商店路线另行确认。

## 7. 推荐的下一步

先锁定喜欢的主题，用 Swift 实现应用/窗口、共享采集、调度和原生主题模型，以一个文字/圆环主题实施 P1 和 P2。然后接通一个真实 Lua/Cairo 主题。Conky 的模板行为作为参考，按样本实现必要子集；Stats 的采集算法与映射按需提取。原生与兼容路径分别测量，先消除重复采集、解析和重绘，再依据 profile 优化。

本阶段可行性调研已完成；下一阶段的依赖安装和功能实现尚未开始。若所需依赖只能通过新增全局 Homebrew 包提供，需就具体依赖取得授权；项目内或可丢弃隔离环境优先。
